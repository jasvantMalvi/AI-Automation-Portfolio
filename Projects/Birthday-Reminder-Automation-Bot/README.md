# Birthday Reminder Automation Bot

A scheduled birthday-wishing workflow built with n8n, Google Sheets, OpenAI GPT-5 Mini, and the WhatsApp Business Cloud API. It runs daily at 9:00 AM, reads contact records from a Google Sheet, filters contacts whose birthday matches the current month and day, generates a personalized WhatsApp message, sends it, and updates the matching contact record with the wish-sent status and date.

> **Important:** The supplied workflow export contains a hard-coded WhatsApp recipient number. As exported, all generated birthday messages are sent to that one number rather than each contact's `Phone Number`. The public workflow JSON replaces the number with a placeholder. Configure the recipient mapping correctly before enabling the workflow.

## Workflow Overview

The supplied export contains **7 functional nodes**:

```text
Schedule Trigger (daily at 9:00 AM)
                ↓
       Get row(s) in sheet
                ↓
       Code in JavaScript
       (select today's birthdays)
                ↓
             AI Agent
                ↓
          Send message
                ↓
       Update row in sheet
```

`OpenAI Chat Model` is connected to the AI Agent as its language model.

## Workflow Stages

### 1. Schedule Trigger

`Schedule Trigger` starts the workflow every day at **9:00 AM**. The exported workflow does not explicitly set a timezone, so confirm the n8n instance/workflow timezone before relying on the intended local send time.

### 2. Read Birthday Records

`Get row(s) in sheet` retrieves the contact records from the `Sheet1` tab in the `Birthday Reminder Bot` Google Spreadsheet.

The supplied sample sheet uses these columns:

| Column | Purpose |
|---|---|
| `ID` | Unique contact identifier |
| `Full Name` | Recipient's full name |
| `Birthday` | Date of birth |
| `Phone Number` | WhatsApp destination number |
| `Relationship` | Relationship to the contact |
| `City` | Recipient's city |
| `Status` | Active / inactive contact status |
| `Birthday Wish Sent` | Whether a wish has already been sent |
| `Last Wish Date` | Date the last birthday wish was recorded |

### 3. Select Today's Birthdays

`Code in JavaScript` runs once for all incoming records and filters the contacts.

It:
- Skips records without a birthday.
- Skips contacts whose status is present and is not `Active`.
- Skips a contact when `Birthday Wish Sent` is `Yes` and `Last Wish Date` equals today's date.
- Compares the birthday month and day with the current month and day, ignoring the birth year.
- Returns the matching contact details, including the row number, phone number, relationship, and today's date.

Only matching records continue to the AI Agent.

### 4. Generate a Personalized Birthday Wish

`AI Agent` uses **GPT-5 Mini** through `OpenAI Chat Model`.

The prompt provides the recipient's full name, relationship, and city. It asks for a warm WhatsApp birthday message, uses the recipient's first name, includes relevant emojis, and returns only the message text.

**Prompt inconsistency:** the user prompt requests 4–6 emojis, while the system message requests 3–5. Both request a 40–60-word message. Align these ranges to avoid conflicting instructions.

### 5. Send the WhatsApp Message

`Send message` sends the AI-generated text using the WhatsApp Business Cloud API.

**Critical exported configuration issue:** `recipientPhoneNumber` is hard-coded in the supplied JSON as `919173679904`. It is not mapped to the current contact's `phone_number` field from the Code node. If multiple people have birthdays on the same day, the workflow can send every generated wish to the same configured phone number.

To make delivery recipient-specific, configure the recipient field to use the current contact's phone number, for example:

```javascript
{{ $('Code in JavaScript').item.json.phone_number }}
```

Use the expression that matches the actual item context in your n8n version and test with two different test contacts before activating the workflow.

### 6. Update the Contact Record

`Update row in sheet` updates the Google Sheets row using `Phone Number` as the matching column. After the WhatsApp send node succeeds, it writes:
- `Birthday Wish Sent` = `Yes`
- `Last Wish Date` = today's date

It also maps the contact's ID, name, birthday, phone number, relationship, city, and status back into the row.

This helps prevent a second wish to the same contact on the same date, provided the update succeeds and the stored date format matches the date generated by the code.

- **WhatsApp Business Cloud API** — birthday message delivery

## Setup

1. Import `workflow.json` into n8n. The public export is inactive.
2. Create or select a Google Spreadsheet with a `Sheet1` tab and the columns listed above.
3. Replace `REPLACE_WITH_YOUR_GOOGLE_SHEET_ID` in both Google Sheets nodes.
4. Reconnect Google Sheets credentials.
5. Reconnect OpenAI credentials for `OpenAI Chat Model`.
6. Reconnect WhatsApp Business credentials.
7. Replace `REPLACE_WITH_YOUR_WHATSAPP_PHONE_NUMBER_ID` with your WhatsApp Business Phone Number ID.
8. **Fix the recipient mapping:** use the current contact's `phone_number` rather than a single fixed destination number.
9. Confirm phone numbers use the format required by your WhatsApp Business setup, usually country code plus number without spaces or punctuation.
10. Set and verify the n8n timezone so the 9:00 AM schedule and birthday comparison use the intended local date.
11. Align the emoji-count instruction in the AI prompt and system message.
12. Test with at least two different contacts who share today's birthday, confirm each receives a message at their own number, and confirm each row is updated correctly.
13. Activate the workflow only after those tests pass.

## Important Limitations and Production Checks

### 1. All messages are sent to one hard-coded recipient in the supplied export

The WhatsApp node has a fixed `recipientPhoneNumber`. It ignores the dynamic `phone_number` produced by the birthday-filtering Code node. This is a major functional error for a multi-contact birthday reminder. Fix it before using the workflow with real contacts.

### 2. Timezone handling is not explicitly pinned

The Schedule Trigger is set to 9:00 AM, but the export does not define a timezone. The JavaScript also uses local `getMonth()` / `getDate()` and `toISOString()` (UTC) for the sent date. Around midnight, local and UTC dates can differ. Set the workflow timezone and use one consistent timezone/date strategy for matching and duplicate checks.

### 3. The duplicate check depends on exact date formatting

The code compares `Last Wish Date` directly to a `YYYY-MM-DD` string. If Google Sheets returns the stored date in another format, the same-day duplicate guard may not work as intended. Normalize both sides to the same date format before comparison.

### 4. A failed sheet update can allow a repeat message

The message is sent before the sheet is updated. If WhatsApp sends successfully but the Google Sheets update fails, the contact may still appear unwished and be selected again on the next run. Add a delivery log/idempotency key or a pre-send processing status to reduce duplicate sends.

### 5. AI prompt rules conflict slightly

The user prompt specifies 4–6 emojis, while the system prompt specifies 3–5. Select one consistent requirement and test message length and quality.

### 6. The workflow does not validate contact phone numbers

The Code node filters based on birthday and status, but it does not validate phone-number format or confirm WhatsApp eligibility/opt-in. Add validation and respect the contact's consent and WhatsApp messaging requirements before sending.

### 7. No explicit error-handling branch

The supplied graph has no dedicated error path for Google Sheets retrieval, AI generation, WhatsApp delivery, or sheet updates. Add failure logging and notifications before unattended production use.

## Current Project Status

The supplied workflow demonstrates daily scheduling, spreadsheet-based birthday selection, AI-generated wishes, WhatsApp delivery, and wish-sent tracking. The screenshots show sample birthday messages and contact records.
